# Go parity test inventory

Audited 2026-11-14 at commit `f6bff59c4c1646747caced0fbb08388fd66626e0`.
This is the original source-audit snapshot, before implementation. Its links point to the audited commit. No tests, Go builds, provider requests, or deployments were run for that audit. See [migration results](GO-PARITY-REMOVAL.md) for the subsequent implementation and validation.

## What can go

The standalone Go differential harness is already retired. The remaining problem is inside the Rust tests: Go recordings, Go helper semantics, and exact Go output still decide many expectations.

The cheapest removals are recorder-health checks, Go decoder error prose, header capitalization, HTML escaping, sorted JSON members, float display, and framework-specific presentation. Keep the useful validation, redaction, numeric precision, and byte-preservation assertions that some of those tests also contain.

The expensive work is replacing broad translator and executor replays with independently specified protocol tests. Those replays cover real auth, streaming, retry, usage, persistence, and multi-turn behavior. Deleting them wholesale would remove useful coverage.

"Only for Go parity" is an assertion-level judgment. A test can contain both a useful security assertion and a pointless Go-layout assertion. The tables distinguish those cases instead of calling every Go-derived test disposable.

## Scope and ratings

Each row names one Rust test entry point, including the tests generated by the Claude `go_file!` macros. A data-driven loop is one Rust test; its recorded input cases are not counted as separate test functions. The fixture section identifies the broad case sets. Go recorder test functions and the historical Python audit tests have separate inventories because Cargo does not run them.

The inventory includes all Go-named test definitions found in the Rust sources, then adds non-Go-named serializer checks, direct fixture consumers, and WebSocket replay entry points. A Go mention in a comment alone is not enough to call a test parity-only. The keep section makes the important false positives explicit.

| Rating | Difficulty of replacing the useful coverage without Go as the authority |
| --- | --- |
| 1 | Straightforward. Direct Rust assertions or a small input table. Often delete an incidental assertion or rename an existing behavioral test. |
| 2 | Small rewrite. Typed fixtures, explicit acceptance policy, serde values, a fixed clock, or raw-byte edit properties. |
| 3 | Moderate. Local HTTP/WebSocket peer, several state transitions, disk persistence, or shared Home interoperability. |
| 4 | Substantial. Many independent cases, provider evidence to establish, or stateful multi-turn behavior to disentangle. |
| 5 | Large suite migration. Split a broad replay into independently reviewable endpoint and protocol contracts. |

Ratings estimate coverage replacement, not a wholesale production rewrite. They assume the existing mocks, fake Home, private auth-directory helpers, and capture sink remain available. A rating is not a time estimate or evidence that the replacement already exists. No replacement needs to execute Go.

Use `serde_json::Value` equality for generated JSON where meaning is the contract. Use typed structs and enums at external boundaries where the allowed fields and types are known. Preserve unknown fields where the product permits them. Use raw bytes or raw spans for native passthrough and targeted edits: deserializing and reserializing an entire client request would violate existing behavior.

## Recommended order

1. Remove recorder bookkeeping and fixture population assertions when their replay is replaced. They do not test current runtime behavior.
2. Remove exact Go error text, header casing, JSON layout, display formatting, and library error-code assertions. Retain statuses, safe errors, precision, valid output, and protocol fields.
3. Replace small helper goldens with explicit boundary tables and properties. Keep operator-used configuration spellings, saved credentials, and shared Home keys until their compatibility requirements are understood.
4. Split translation and executor replays by supported endpoint and operation. Start with one complete provider or route, including failure and streaming behavior, before removing that replay.
5. Remove the Go recording toolchain and stale regeneration instructions once no active test needs its expectations. Preserve historical provenance as history rather than regenerating it to justify behavior.

Codex replacements must follow [the Codex contract](codex/CONTRACT.md), with unknown behavior left unknown. Other providers need their own documentation, first-party clients, or verified wire behavior as evidence. A local mock proves the proxy follows a chosen contract; it does not prove provider acceptance.

Changing cache semantics also retains the existing live cache-read/cache-write requirement before merge. This audit changes only this document.

This file inventories tests; it does not silently change those rules. Removing a test expectation and changing an accepted config, shared key, or native payload are different decisions.

## Audit method and limits

The inventory was built from Rust test attributes, Go-related test names, fixture includes and fixture-loader callers, generated Claude tests, and WebSocket replay entry points. The audit then inspected assertions, replay logic, fixture provenance, reference writers, and the current CI workflow. It checked Go-named candidates against the final per-test rows and checked source-link targets and line numbers.

Useful searches to repeat on a newer revision:

```sh
rg -n 'golden|parity|matches_go|like_go|encoding_json|gjson|sjson|gorilla|GoStr' crates --glob '*.rs'
rg -n 'include_(str|bytes)!|go_file!|go_file_v8_0_27!|go_file_v8_0_35!' crates --glob '*.rs'
rg -n '^func Test' crates --glob '*.go' --glob '*.go.txt'
rg -n '^    def test_' docs/parity-audit/test_audit.py
```

This is source evidence, not a compiled test list or a passing test receipt. Conditional and optional-feature tests are included where identified. Pure protocol known-answer tests, ordinary tests that only mention Go as history, vendor dependencies, old captured outputs, and removed-provider fixtures without active consumers are not classified as active Go-parity obligations merely because their provenance mentions Go.
